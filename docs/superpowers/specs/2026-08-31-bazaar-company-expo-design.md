# 创司集市：一人一司 AI 产品展评

> 状态：**待用户确认书面规格**  
> 日期：2026-08-31  
> 形态：Work Ally 内置办公应用（租户级），视觉为「科技展会」  
> 实现路径：方案 2（摊位集市版）

## 目标

在企业租户内提供一款**轻社交解压应用**：每人开一家虚构公司、开发虚拟 AI 产品、摆摊展览；同事浏览并打星；按**产品分**冲榜（行内带出员工姓名）。

- 不是真实业务系统，不映射真实职级/部门
- 不做成重度经营养成；核心是「发布 → 逛展 → 打星 → 上榜」
- AI 只用于**润色产品文案**，不直接加分

## 已拍板决策

| 议题 | 结论 |
|---|---|
| 参与模型 | 一人一司（非全员共建一家公司） |
| 岗位映射 | 纯虚构，与通讯录无关 |
| 产品主题 | 虚拟世界里的 AI 相关产品创意 |
| 创作方式 | 填卡片为主 + 一键 AI 润色（确认后写入） |
| 评分 | 1～5 星；每人每产品一条，可修改 |
| 计分对象 | **单个产品**（非个人累加总分） |
| 计分公式 | `产品分 = 20 + Σ(他人给出的星级)` |
| 自评 | 禁止给自己的产品打星 |
| 榜单 | **产品榜**；每行：`员工姓名 · 公司名 · 产品名 · 产品分` |
| 视觉 | 科技展会（深色展台 / 霓虹分区） |
| 货架上限 | 同时上架 ≤ 8 件（可下架腾位） |
| 可见范围 | 仅本租户成员 |
| slug / 路由 | `bazaar` → `/workbench/apps/bazaar` |
| 对外名 | 创司集市 |

## 产品定位

**租户内的虚拟 AI 产品展会：摆摊、逛展、打星、冲产品榜。**

比聊天更适合「扫一眼别人的脑洞」；比经营游戏更轻——无研发进度条、无资源生产。

### 刻意不做（v1）

- 全员共建一家公司 / 部门分工决策
- 养成进度、赛季清零、跨租户对打
- 评论区、私信、关注粉丝
- 真实商品/支付/外链跳转商店
- 图片上传（v1 用渐变封面色或预设皮肤代替）
- 点赞替代星级（已定星级）

## 核心循环

1. **开公司**：起名、一句 slogan、选摊位皮肤（少量预设）
2. **上新品**：名称 / 卖点 / 功能点 → 可选 AI 润色 → 上架到摊位货架
3. **逛展会**：大厅看最新/最热产品卡；点进详情或进对方摊位
4. **打星**：1～5 星（作者不可评自己的产品）
5. **看榜**：按产品分排序，看见同事姓名与作品

## 信息架构

```text
/workbench/apps/bazaar
├── 展会大厅（默认）     最新 | 最热 · 入口：我的摊位 / 排行榜
├── 我的摊位             公司头图 + 货架（≤8）· 新建/编辑/下架/润色
├── 他人摊位             只读货架
├── 产品详情             介绍 + 打星 + 跳转作者摊位
├── 排行榜               产品分列表
└── 开公司引导           首次进入且无公司时
```

包在现有 `WorkbenchShell` 内，接入方式对齐闪签 / 笔记。

## 界面与交互（科技展会风）

### 展会大厅

- 顶栏：应用名 +「我的摊位」「排行榜」
- Tab：最新 / 最热
- 产品卡网格：封面渐变、产品名、`姓名 · 公司`、均星与产品分
- 未开公司时，「我的摊位」引导去开公司；有公司时可快捷「+ 上架新品」

### 我的摊位

- 公司条：皮肤/头图、公司名、slogan、员工姓名、编辑公司
- 货架计数 `n / 8`
- 已上架卡片：编辑、下架、AI 润色
- 空位：新建产品卡片（草稿可先存，上架才占货架名额并进入大厅/榜）

### 产品详情

- 封面、标题、作者与公司（可进摊位）
- 卖点正文、功能点列表
- 打星区：五星控件；展示当前产品分与「基础 20 + 他人星级合计」说明
- 若当前用户是作者：隐藏打星，仅显示统计

### 排行榜

- 按 `score` 降序
- 行格式：`#N 员工姓名 · 公司名 · 产品名` + 右侧分数
- 可附均星、评分数（次要信息）

## 计分与防刷（细则）

| 规则 | 说明 |
|---|---|
| 基础上架分 | 首次变为 `published` 时记入基础分 20；下架再上架不重复叠加基础分（分值按当前评分重算，基础分仍计一次逻辑：公式恒为 `20 + Σ stars`，与历史上架次数无关） |
| 星级加分 | 每位他评用户贡献 `stars`（1～5）；改星则替换，不叠两笔 |
| 重算时机 | 创建/修改/删除评分后更新该产品的 `score`、`ratingCount`、`avgStars` |
| 同分排序 | 评分人数多者优先，再比 `updatedAt` 新者优先 |
| 信息门槛 | `title`、`pitch` 非空才可上架 |
| 租户隔离 | 列表、详情、评分、榜单均强制 `tenantId` |

**均星展示**：`avgStars = Σ stars / ratingCount`（无评分时不展示或显示「暂无评分」）。

## 数据模型

均带 `tenantId`；命名前缀 `Bazaar*`。

### `BazaarCompany`

- `id`, `tenantId`, `userId`
- `name`（公司名）, `slogan`, `stallSkin`（预设枚举字符串）
- `createdAt`, `updatedAt`
- `@@unique([tenantId, userId])` — 一人一司

### `BazaarProduct`

- `id`, `tenantId`, `companyId`, `userId`（冗余便于鉴权与榜单 join）
- `title`, `pitch`（卖点长文）, `featuresJson`（`string[]`，最多 8 条，每条 ≤ 40 字）
- `coverHue` Int（0–359，用于渐变封面；v1 无上传图）
- `status`: `draft` | `published`
- `score` Int, `ratingCount` Int, `avgStars` Decimal(3,2)
- `publishedAt` DateTime?
- `createdAt`, `updatedAt`
- 索引：`[tenantId, status, publishedAt]`；`[tenantId, status, score]`；`[tenantId, companyId]`

### `BazaarRating`

- `id`, `tenantId`, `productId`, `userId`, `stars` (1–5)
- `createdAt`, `updatedAt`
- `@@unique([productId, userId])`
- 服务层拒绝：`userId === product.userId`

## API（前缀 `/apps/bazaar`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST/PATCH | `/company` | 读/建/改我的公司 |
| GET | `/company/:userId` | 他人公司（只读） |
| GET/POST | `/products` | 我的产品列表 / 创建草稿 |
| GET/PATCH/DELETE | `/products/:id` | 读/改/删（作者） |
| POST | `/products/:id/publish` | 上架（校验货架 ≤8、字段门槛） |
| POST | `/products/:id/unpublish` | 下架（保留评分数据；大厅与榜不可见） |
| POST | `/products/:id/polish` | AI 润色，返回建议文案，客户端确认后再 PATCH |
| GET | `/market` | 集市流：`sort=newest`（`publishedAt` desc）\|`hottest`（`score` desc，同分 `ratingCount`） |
| GET | `/stalls/:userId` | 摊位：公司 + 已上架产品 |
| PUT | `/products/:id/rating` | 打星/改星 `{ stars: 1..5 }`（v1 不提供取消评分，改星即可） |
| GET | `/leaderboard` | 已上架产品按 score 排序，附带 `userName`、公司名、产品名 |

鉴权：登录 + 本租户；应用启用守卫对齐 `StickiesAppGuard` / `NotesAppGuard`。

AI 润色：使用该应用在 `AppRegistry` 上绑定的 `defaultModelConfigId`；未配置时返回明确错误提示管理员配置。

## 接入 App Registry

- 默认项：`slug: bazaar`，`name: 创司集市`，`description: 一人一司的虚拟 AI 产品展会：摆摊、逛展、打星冲榜`
- 管理员可启用/停用、绑定默认模型（润色）
- 工作台应用列表增加展会风封面样式（深色霓虹卡）

## 错误与边界

| 场景 | 行为 |
|---|---|
| 未开公司就建产品 | 409/引导先开公司 |
| 上架超过 8 | 400，提示下架腾位 |
| 自评 | 403 |
| 给未上架产品打星 | 404/400 |
| 润色无模型 | 503/400，文案提示配置模型 |
| 删产品 | 级联删除其评分；若需保留历史榜可改为仅下架（v1 允许作者删除，确认文案提示不可恢复） |

## 测试要点（验收）

1. 租户 A 成员看不见租户 B 的公司/产品/榜
2. 一人只能有一家公司
3. 上架第 9 件失败；下架后可再上架
4. 作者无法给自己打星；他人可改星且分数按新星重算
5. 榜单行含姓名·公司·产品·分，且按下架后消失
6. AI 润色不改库，确认 PATCH 后才变
7. 基础分不因反复上下架叠加（公式始终 `20 + Σ`）
